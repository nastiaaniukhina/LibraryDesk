| Входить | Свідомо не входить |
| --- | --- |
| облік читачів, книжок, видач | бази даних, мережеві сервіси |
| видача книжок і прийом повернення | оплата штрафів через банк |
| розрахунок плати і пені за прострочення | інвентаризація примірників |

| пошук видач і звіт «боржники на дату» | графічний інтерфейс, веб |
| зберігання у JSON | резервне копіювання в хмару |

### UC-01. Забронювати книжки

- **Дійова особа:** бібліотекар.
- **Мета:** зарезервувати обрані примірники книжок для читача.
- **Передумова:** читач зареєстрований у системі, обрано одну або кілька позицій із коректним ISBN, денною ставкою та кількістю.
- **Основний перебіг:**
  1. Бібліотекар вказує ідентифікатор читача, тип читача та перелік книжок для бронювання.
  2. Система перевіряє коректність вхідних даних і наявність хоча б однієї позиції.
  3. Система формує нову видачу у стані `Reserved` із переданими позиціями.
  4. Система зберігає нову видачу у сховищі.
  5. Система повідомляє про успішне створення бронювання та повертає ідентифікатор видачі.
- **Альтернативи:**
  - `1а.` Перелік позицій порожній або відсутній: система відхиляє бронювання, стан не змінюється, у журнал записується попередження.
  - `2а.` Некоректний ідентифікатор читача, порожній ISBN або недопустимі значення кількості чи ставки: система відхиляє запит і просить повторити введення.
- **Постумова:** у сховищі з'явився новий запис видачі у стані `Reserved` із зафіксованими позиціями.
- **Правила:** видача починає життєвий цикл зі стану `Reserved`; до видачі додається принаймні одна позиція; у журнал пишуться лише ідентифікатори без персональних даних.
- **Імена тестів:** `Place_ValidItems_CreatesReservedLoan`, `Place_EmptyItems_ThrowsDomainRuleException`.

### UC-02. Видати книжки

- **Дійова особа:** бібліотекар.
- **Мета:** видати заброньовані книжки читачеві та встановити строк повернення.
- **Передумова:** у системі існує видача у стані `Reserved` із заповненими позиціями.
- **Основний перебіг:**
  1. Бібліотекар вказує номер видачі та строк користування (або дату повернення `DueAt`).
  2. Система знаходить видачу за номером.
  3. Система перевіряє, що поточний стан видачі — `Reserved`, і переводить видачу у стан `Issued`.
  4. Система виставляє дату повернення `DueAt` на основі поточного часу та строку користування.
  5. Система зберігає оновлену видачу у сховищі та надсилає сповіщення.
- **Альтернативи:**
  - `1а.` Номер видачі некоректний або не знайдено: система відхиляє операцію, стан видач не змінюється, у журнал записується `Warning`.
  - `2а.` Видача перебуває не в стані `Reserved` (наприклад, `Issued`, `Overdue`, `Returned` або `Cancelled`): перехід заборонено, стан не змінюється, у журнал записується `Warning`.
- **Постумова:** видача має стан `Issued` і встановлену дату `DueAt`, зміни збережено у сховищі, сповіщення зафіксовано.
- **Правила:** дозволений перехід лише `Reserved → Issued`; час береться через годинник системи, без прямого виклику системного годинника в домені.
- **Імена тестів:** `Issue_ReservedLoan_TransitionsToIssuedAndSetsDueAt`, `Issue_NonReservedLoan_ThrowsInvalidLoanStateException`, `Issue_MissingLoan_ThrowsLoanNotFoundException`[cite: 2].

### UC-03. Прийняти повернення

- **Дійова особа:** бібліотекар.
- **Мета:** прийняти книжки від читача, закрити видачу та за потреби нарахувати пеню.
- **Передумова:** у системі існує видача у стані `Issued` або `Overdue`.
- **Основний перебіг:**
  1. Бібліотекар вказує номер видачі для повернення.
  2. Система знаходить видачу за номером.
  3. Система перевіряє, що стан видачі дозволяє повернення (`Issued` або `Overdue`).
  4. Система обчислює дні прострочення та пеню за правилами для категорії читача.
  5. Система переводить видачу у стан `Returned` і фіксує момент повернення.
  6. Система зберігає видачу, надсилає сповіщення та виводить підсумок (окремим рядком — пеню, якщо є прострочення).
- **Альтернативи:**
  - `1а.` Видачу не знайдено: повідомлення, стан не змінюється, у журнал `Warning`.
  - `2а.` Видача в стані `Returned` або `Cancelled` (чи `Reserved`): операція відхиляється, стан не змінюється, у журнал `Warning`.
  - `4а.` Прострочення є: система рахує пеню і показує її окремим рядком.
- **Постумова:** видача переведена у стан `Returned`, зафіксовано час повернення, розраховано підсумок і пеню, дані збережено.
- **Правила:** повернення можливе лише зі станів `Issued` та `Overdue`; пеня рахується за таблицею рішень та обмежується верхньою межею.
- **Імена тестів:** `ReturnLoan_OverdueIssuedLoan_CalculatesPenaltyAndMarksReturned`, `ReturnLoan_AlreadyReturned_ThrowsInvalidLoanStateException`, `ReturnLoan_MissingLoan_ThrowsLoanNotFoundException`.

### UC-04. Скасувати бронь

- **Дійова особа:** бібліотекар.
- **Мета:** скасувати активне бронювання книжок до моменту видачі.
- **Передумова:** у системі існує видача у стані `Reserved`.
- **Основний перебіг:**
  1. Бібліотекар вказує номер видачі для скасування.
  2. Система знаходить видачу за номером.
  3. Система перевіряє, що стан видачі — `Reserved`.
  4. Система переводить видачу у стан `Cancelled`.
  5. Система зберігає оновлену видачу та надсилає сповіщення.
- **Альтернативи:**
  - `1а.` Видачу не знайдено: повідомлення, стан не змінюється, у журнал `Warning`.
  - `2а.` Видача не у стані `Reserved` (наприклад, `Issued`, `Overdue`, `Returned` або вже `Cancelled`): скасування відхиляється, стан не змінюється, у журнал `Warning`.
- **Постумова:** видача має стан `Cancelled`, зміни збережено у сховищі, сповіщення надіслано.
- **Правила:** скасувати можна лише видачу у стані `Reserved`; перехід у `Cancelled` незворотний.
- **Імена тестів:** `Cancel_ReservedLoan_TransitionsToCancelled`, `Cancel_IssuedLoan_ThrowsInvalidLoanStateException`, `Cancel_MissingLoan_ThrowsLoanNotFoundException`.
