# Стандарт кодування проєкту LibraryDesk

## 1. Загальні положення

1.1. Стандарт обов'язковий для всього коду в рішенні LibraryDesk.
1.2. Імена в коді англійською, коментарі й документація українською.
1.3. Платформа: .NET 9, C#, Nullable та ImplicitUsings увімкнено.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | LoanItem | loanitem |
| Інтерфейс | I + PascalCase | ILoanRepository | Repository |
| Метод | PascalCase, дієслово | CalculateTotal | calc |
| Властивість | PascalCase, іменник | DailyRate | GetDailyRate |
| Приватне поле | _ + camelCase | _items | m_Items |
| Локальна змінна | camelCase | totalAmount | ta |
| Константа | PascalCase | MaxLoanDays | MAX_DAYS |
| Перелічення | PascalCase, однина | LoanStatus | LoanStatuses |

## 3. Форматування

3.1. Відступ: 4 пробіли, табуляція заборонена.
3.2. Довжина рядка: не більше 100 символів.
3.3. Фігурні дужки: стиль Allman, обов'язкові навіть для однієї інструкції в `if`.
3.4. Між членами класу: рівно один порожній рядок.
3.5. Директиви `using`: на початку файлу, системні першими, невживані видаляються.
3.6. Простір імен: файлового рівня (`namespace X;`).
3.7. Файл закінчується одним символом нового рядка, пробілів наприкінці рядків немає.

## 4. Коментарі та документація

4.1. Коментар пояснює «чому», а не «що».
4.2. Кожен публічний тип і член бібліотеки має XML-документацію `/// <summary>`.
4.3. Закоментований код у репозиторії не залишається.

```csharp
// погано: коментар переказує код
// додаємо один день
days = days + 1;

// добре: коментар пояснює причину рішення
// бібліотека рахує початий день як повний, тому тут Ceiling
days = (int)Math.Ceiling(totalHours / 24.0);
```

## 5. Структура проєкту

5.1. `LibraryDesk.Core`: уся логіка предметної області, без `Console`.
5.2. `LibraryDesk.App`: лише введення й виведення, посилається на Core.
5.3. Класи предметної області лежать у теці `Domain`, один тип на файл, ім'я файлу збігається з ім'ям типу.

## 6. Правила комітів

6.1. Формат повідомлення: `тип: коротка суть` (Conventional Commits).
6.2. Дозволені типи: feat, fix, docs, chore, style, refactor, test.
6.3. Повідомлення в наказовому способі, один коміт відповідає одній завершеній зміні.
6.4. Теки `bin` і `obj` до репозиторію не потрапляють.
